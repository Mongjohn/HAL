# HAL behavior and decisions

This is the behavior contract and rationale for ongoing development. Read it with [the development handoff](DEVELOPMENT.md) and [the user guide](../README.md). Source references below are relative to `app/src/main/java/com/evofactory/hal/` unless stated otherwise. The 2026-11-16 review used `0fa2ee2` as its baseline. Later updates cover browser settings and Restore from PR #10 and the softer Glass palette.

## Native launcher and configuration ownership

HAL is a native Kotlin/Compose Android TV launcher, not a website displayed on a TV. Its Android package is `com.evofactory.hal`. Home Assistant, RTSP cameras, and Frigate are optional. Home remains useful as an app launcher without them.

The browser editor owns dashboard layout, content, names, visibility, and all settings import/export. The TV settings own integration setup, top-bar actions, launcher behavior, appearance, and artwork source. This keeps layout editing and file handling accessible from a phone or computer. The editor is bundled in the APK so it works without a hosted editor service.

Copying a Home Assistant dashboard creates an independent HAL layout. It does not modify the HA dashboard or keep layout changes synchronized. Entity states still update live. Legacy display settings and the old app-selection keys remain as migration inputs; their presence in code is not a reason to restore the removed TV layout menus or dock.

The user retired the Assistant dashboard on 2026-11-20 because Home supports the same card types and controls. The TV tab, browser surface choice and blue remote shortcut are removed in every theme. Saved Assistant cards migrate once into additional Home views after the effective Home layout and any legacy template are available. Existing Home pages and positions stay intact; imported pages are labeled “Imported · …”, colliding card keys receive unique replacement keys, and visibility, item spacing, widths, headings and Home focus are retained. Home aliases/names take priority for duplicate entity IDs because Home now has one shared naming scope. Missing manual selections from the old Assistant selection can be seeded as extra views. Migration persists the combined Home layout and clears the live Assistant surface. A TV-local retirement marker prevents reseeding from obsolete template settings on later launches.

Old version 1 settings files remain supported. An Assistant-only layout becomes Home; a file with both layouts merges them before replacing Home. Reimporting a file replaces Home rather than repeatedly appending to the TV’s current layout. The 64-view and 10,000-name limits accommodate the union of the former 32-view / 5,000-name surfaces; larger combined files are rejected before saving. Legacy model/backup decoding fields and an empty compatibility state object remain, but no separate Assistant dashboard is exposed. If an old Home template needs to load for migration, retirement waits for that template or the server’s missing-template result so it does not overwrite it with a guessed layout.

## Grid, contents, and remote navigation

Home has up to 64 views. A view has 1–24 total columns and 1–6 columns on screen; **Auto** shows all columns up to six. Explicit positions and spans survive horizontal scrolling. The viewport has 15 grid rows; increasing grid resolution must not increase the dashboard's physical height. Cards are at most one viewport tall and scroll their content internally. Views can extend vertically beyond that viewport. The Home camera remains outside the editable card grid in its fixed position, and its area is reclaimed when absent.

These choices preserve a deliberate arrangement and make the preview useful for TV placement. Do not compact whole-card gaps when visibility changes. Left/Right navigation searches across gaps and brings off-screen targets into view. Changing views resets both scroll directions. Keep normal header spacing and the clock's screen inset as the reference for outer margins.

Card titles and subheadings are optional. A subheading belongs before an item or after the final item; clearing it removes the occupied heading space. Ordinary rows can be half width, pairing adjacent eligible items unless a heading or full-width row interrupts them. Weather, gauges, graphs, and dedicated media panels remain full width. The saved `twoPerRow` field is a fallback for older layouts; explicit per-item widths take precedence.

Ordinary cards have two navigation levels: focus the card, then press OK to enter its controls. **Apps** is the exception: entering it focuses an app tile immediately, and OK launches it. There is at most one Apps card, across all Home views. It inherits the old dock selection and order, retains **All apps**, and fits artwork without cropping. At a tile boundary, move to a neighboring card when one exists; dead side edges retain the current tile. Preserve the Up route to the header.

**HAL settings → Appearance → Collapse Apps card** saves **Off**, **Up**, or **Down** on the TV, defaulting to Off for existing and new installations. Existing saved choices carry forward. Up and Down collapse the drawing toward that edge when focus leaves or after 30 seconds idle while focused, revealing an Apps label. This supersedes the earlier focus-always-keeps-it-open behavior. Geometry and focus targets stay in place. Entering from outside opens the card normally. If it collapses while focused, the next key only expands it: consume its press, repeats and release, including shortcuts and Home intercepted by HAL's helper. Power passes through normally. Held keys defer collapse until 30 seconds after release. An app context menu keeps it expanded; menu dismissal and foreground return start a fresh timeout. Off disables both kinds of collapse.

The top bar's color-filter layer has bottom drawing clearance for growing focused buttons and their labels. This keeps the Settings and network circles complete during color cycling without moving their anchors, dropdown or dashboard.

Normal navigation remembers the last available app tile. A handled remote Home press deliberately starts at the first visible tile in grid order instead. **Focus on Home press** is unique across Home views. HAL checks live card visibility before routing and again after switching view. It passes the request directly to the card, waiting for the app list when needed; the earlier explicit header-focus step was removed because it visibly flashed Home before selecting an app. The Home button is temporarily ineligible for focus while a request is pending. A hidden, absent or unfocusable target falls back to the header, and the request is consumed after the attempt. When Home is the only tab it is a static label, and header fallbacks use the network button. Cameras/Alerts retain selectable tabs when configured.

**Cameras** exists only with configured cameras; **Alerts** exists only with configured Frigate. Their color shortcuts have the same availability checks. If the current tab disappears, return to Home. Setup remains reachable from the cog so removing an empty tab never removes the path to configure it.

## State cues and actions

Use icons and restrained colors to make state readable from a TV viewing distance: warm amber for active lights, green for locked, red for unlocked. Omit duplicate visible state text or switches only when the icon already communicates that state. Keep numeric values, units, and unfamiliar states readable. A simpler appearance must not remove remote OK behavior.

Choose a primary action from the latest HA state when activated, with feature checks where the domain advertises them. Unknown, unavailable, and unsupported states produce no primary service call. Locks alternate lock/unlock; supported covers and valves open/close; media players choose pause, play, or power from state and capabilities; vacuums prefer return-to-base over stop while cleaning. Selects retain their menus, and scenes, scripts, and buttons retain their action paths. A recognized entity type does not imply HAL implements every control it exposes in HA.

Cards configured exclusively with standard media-player readings get one full-width panel per player and no containing frame. Their visible panel outlines align to the grid slot. Headings sit inside the panels, and the panels share spare height so the group fills the slot when it fits. Tall content scrolls inside the slot. Mixed cards use the shared frame and ordinary rows, with media icons and labels on the same content inset as the other readings. Classification follows configured contents. At card-level focus, highlight all visible player panels. After OK, highlight only the selected player. Short cards use the compact presentation. Taller cards expose more metadata and progress. The panel invokes the supported primary action.

Player artwork uses the available panel height up to a width limit that leaves room for readable metadata. Titles and headings retain their space. Progress sits alongside the artwork so it can use the available height. HA artwork is decoded off the main thread at a bucketed display size with a maximum decoded edge. Media artwork sends HA authorization only to the configured origin (scheme, host, and port). External artwork uses HTTPS without that token, and redirects are disabled for this request path.

Playback progress uses a monotonic clock between HA updates because position reports may be sparse. A fresh usable timestamp anchors the sample. Otherwise HAL uses receipt time. Unrelated attribute changes preserve progress. Pause freezes it, and new position or track samples resynchronize it. The progress bar reads its clock during drawing, and the elapsed label updates at whole-second boundaries.

## Conditional visibility

Rules can belong to a whole card, an entity row, or an Apps tile. HAL-authored comparisons use exact, case-sensitive HA state strings, with **Is any of** or **Is none of**. Group operations are **All conditions match**, **Any condition matches**, and **At least one condition fails**. The last is NOT(AND), not “none match.” A missing entity produces an indeterminate result for a HAL-authored rule. Show content only when the result is definitely true; a decisive false in All or true in Any can settle a group even if another input is missing. Literal `unknown` and `unavailable` values received from HA can themselves be compared.

Imported HA rules retain their separate comparison semantics: entity-looking comparison values can reference another entity, and a missing subject is treated as `unknown`. This distinction prevents importing a rule from silently changing its meaning. Supported imports include legacy state syntax, state/state_not, nested and/or/not, conditional wrappers, and per-card visibility. Attribute, duration, numeric, screen, user, and other unsupported conditions are not general-purpose supported rule types. A card with invalid or unsupported visibility is skipped with an import notice rather than made unconditionally visible.

Subscribe to rule-only entities and comparison entities even when they appear nowhere in card contents. The first subscription snapshot after reconnect replaces stale membership; otherwise removed entities could keep old visibility decisions alive. Flattening HA sections must preserve each conditional scope, without applying a nested condition to unrelated siblings.

Hidden whole cards retain their grid positions. Hidden items default to **Release space**, allowing later items to reflow; **Keep space empty** preserves their slots. Hidden items never remain navigation targets. Row rules follow configured row indices when reordering, including gauge and graph entries. App rules follow app IDs. Delete the rule with its item. Optional saved fields keep older layouts loadable.

The browser keeps conditional content editable; it is a layout preview, not a live HA-state simulator or a pixel-identical TV rendering. It shows entity labels and half-width row placement; Apps previews currently list only the first eight app labels rather than rendering the TV tile grid, and media artwork/controls are not reproduced. Removing the last rule/group clears visibility. Incomplete rules take the user to the relevant card or item disclosure before Apply can succeed.

## Browser session and saving

The Settings cog order is HAL, Home Assistant, Cameras, Frigate, Android TV, Enable Web Editor. The toggle starts HTTP on port 8765 and opens a URL/QR popup. Closing that popup leaves the listener running; switching the toggle off stops it. There is no idle timeout. The running listener keeps HAL's foreground view awake, because screensaver activation previously interrupted editing. This is session state, not a persisted always-on server: activity/process teardown closes it and a fresh launch starts disabled. It does not lock the user into HAL or promise background-service availability.

No pairing is a deliberate local-network usability choice. The listener binds a selected Wi-Fi/Ethernet IPv4 address, restricts peers to that interface's subnet, checks Host/Origin and cross-site headers, and limits request sizes. The editor uses unencrypted HTTP. State, catalog, and settings-choice responses omit credentials. An explicit settings-file export can return selected logins or camera URLs with credentials. Use the displayed IP address and restart editing after an address change if the old URL stops working.

**Apply to TV** sends the selected surface with the listener's revision. A stale revision is rejected, rather than overwriting a newer editor save. Success requires an explicit `applied` response and a new revision; an unconfirmed response retains the browser draft. A lost response can still follow a successful TV update, so “unconfirmed” does not mean “definitely unsaved.” The current implementation updates in-memory state and queues a SharedPreferences write; it does not guarantee a completed disk flush.

Each Apply saves a restore point for Home. The first Apply can save the effective layout seeded from legacy settings. Restore consumes the checkpoint and replaces the Home draft; Browser Undo edits the draft. Earlier releases had independent Home and Assistant restore points, and those legacy storage fields remain readable. Retiring Assistant invalidates checkpoints for layouts changed by that migration. The web editor no longer offers or accepts Apply/Restore for Assistant; the Home-focus target is unique within Home.

The user chose the browser as the single import/export workflow. The TV-to-TV protocol, discovery permission, and dialogs were removed. Copy settings between TVs by exporting a file in one TV's editor and importing it in the other's.

The browser exports selected saved TV settings in version 1 HAL JSON. It previews the file's selectable contents before applying changes. Camera and integration login choices start unchecked because their payloads can contain credentials. Cameras and entity selections merge, selected logins replace their saved values, and imported dashboards replace Home after normalization of any legacy Assistant content. Import clears the restore point for each layout it changes. Confirmed imports reload the Home draft from saved state, discarding unapplied edits, and refresh the Home Assistant catalog. A reload or catalog failure after confirmation is reported separately. The UTF-8 JSON request body for preview or import must fit within 4 MiB, including the wrapper and any selection keys.

The versioned file covers selected layouts, app settings, cameras, entity settings, and integration logins. Earlier version 1 files still import. A legacy app-tile list can update the Home Apps card when the file selection supplies no Home layout. Uploaded artwork, appearance, and artwork-source settings are outside the file's scope.

Drag steps use rendered track widths, gaps, and scroll deltas so diagonal moves and narrow previews remain accurate. Drag title/grip; resize at the lower-right handle. Swap only when both cards fit. Changing Column in the sidebar tries the current row, then the nearest free row in that column, leaving other cards in place. The 16:9 preview keeps its footprint when empty and scrolls overflow inside it.

Use the same keyboard-friendly entity picker in Contents and Visibility. Room and Type narrow the result set; every case-insensitive search word must match somewhere in the name or ID, in any order. Friendly-name overrides apply throughout Home, not globally in HA. Keep secondary row settings collapsed and whole-card versus item visibility clearly separated.

JSON requests are explicitly decoded as UTF-8, including requests without a charset. This prevents new label corruption but cannot recover replacement characters already saved. Compare overrides against the HA catalog and repair or clear the affected labels, then save/read back. LastPass errors previously seen in `8.packages.js` and `30.infield.js` belong to the extension; use a clean browser profile to establish ownership before changing HAL.

## Artwork, appearance, and idle behavior

Artwork is opt-in. **Use local artwork** selects a source explicitly: on means uploaded files, off means media artwork. Do not switch sources implicitly when local files are added or removed. If no selected image can load, use black with the dashboard still visible. If a current eligible image loaded and other images fail, the rotation can retain it.

Media artwork uses JustWatch regional release pages without an API key, filtered by saved country and selected subscriptions. “Recent” refers to arrival on a streaming service, while the caption year is the title's original release year. Titles are deduplicated and capped at 20. A title-page backdrop is preferred, with a poster fallback. Android schedules a network-required refresh roughly every 24 hours and checks freshness on startup/settings changes; this is not an exact-time job. Local mode or a disabled slideshow cancels catalog jobs. Matching cached metadata and cached images can help through outages but do not guarantee offline artwork.

Watch Next supplies eligible images from supported apps in the launcher app selection. Explicitly paid entries are excluded; unknown availability is not proof of a subscription. The merged rotation is **catalog first, then Watch Next**, deduplicated by URI and capped at 20; a full catalog excludes Watch Next entries from that pass. Conditional hiding of an Apps tile does not currently filter the separate artwork app-selection list. No generic unrelated-artwork fallback is used.

Local uploads allow 20 JPEG/PNG/WebP files, each at most 8 MiB and 8192 pixels in either dimension. Validate actual decodable image content, confine file operations to private `files/slideshow-artwork`, reject symlinks, and use generated IDs. Filenames are sanitized to ASCII stems; captions omit the generated ID and extension. Upload/delete takes effect independently of Apply to TV. Local images are not included in settings exports.

The rotation shuffles at startup and between passes, remembers the last image, and defers it when another can load. Slides stay about 45 seconds with a 1.2-second crossfade, behind a dark overlay. This varies the artwork without hiding the dashboard or preventing Android's ordinary screensaver handoff. Watch Next's former dashboard row and chevrons are removed.

**HAL settings → Appearance** offers **Glass**, **Glass Dark**, and **Calm**. Glass is the default for upgrades and new installations. HAL ignores retired theme selections and saves the current choice per TV. Glass Dark keeps the Glass layout and material styling with a black base, deeper fills, subdued focus and state colors, and dimmer text. At the user's request, all themes use Glass's slideshow shade for local and media artwork alike; this replaces Glass Dark's stronger shade. The camera screensaver uses the selected palette for its controls and text. All themes share the saved card-fill opacity override, including 0% and 100%. **Use theme default** clears the override and restores 50%. Opacity applies to fills. Text, icons, focus outlines, and decorative borders remain visible at zero.

The user requested a new interface inspired by the supplied Android TV launcher video without a rewrite or losing HAL capabilities. **Calm** adds a separate presentation over the existing dashboard model: a quiet overview, horizontal live card summaries, a compact Apps area, a persistent media row, and a focused room/card panel. The clock is on the right, and the generic “Your home, at a glance” line is removed. It reuses the existing weather, controls, selects, gauges, history and media renderers. Summary data excludes conditionally hidden rows, including reserved slots. Missing light states are not described as off. Card and item rules continue to update live. Home targets focus persistent media controls, open an ordinary card's view/panel, or focus the first visible Apps tile; ordinary Apps entry keeps the last tile.

Calm does not migrate or rewrite dashboard layouts. Cards follow saved top-to-bottom/left-to-right grid order in the summary rail; original positions and spans are retained for the Glass themes. Per-item widths and reserved slots still apply inside opened panels. Apps keeps configured columns and scrolls vertically if needed. Cameras and Alerts retain their dedicated screens with the Calm palette, and the Home camera retains its fixed adjacent area. The browser preview shows the saved grid rather than the Calm presentation. Back closes the panel in one press and returns to the originating summary; global remote shortcuts dismiss the panel before reaching their normal destinations. The large overview and summaries are hidden behind an opened panel so they cannot show through its translucent fill. Switching theme is TV-local and does not change slideshow source, enable artwork, or change listener/screensaver behavior. No reference-video imagery is bundled.

Calm’s overview measures its full-size stacked text first. If it does not fit above the media/card/Apps rows, it tries a horizontal arrangement. Only if neither fits does it scale the arrangement requiring the least reduction; overview values wrap instead of being ellipsized. Apps reserves one 96 dp viewport and scrolls between full-height rows with D-pad movement. Its configured columns, ordering, hidden/reserved app slots, context menus and idle-collapse semantics remain; Glass keeps the multi-row grid. Focus-driven scrolling snaps to complete row tracks and continues to its selected row when focus leaves.

The small summary lock badge has its own subdued fixed green (locked) and red (unlocked/jammed) palette. It is drawn outside the summary text’s color-cycle filter so that enabled chroma reversal cannot swap the safety meaning of red and green. Other summary controls still cycle. This supersedes cycling that badge with the rest of the summary. These colors do not establish burn-in prevention.

Calm uses flat translucent fills and muted green/ivory accents. It adds no blur, video wallpaper, network polling, or continuous animation. Ordinary cards compose their full controls when opened; their summaries are informational. Media-only cards compose their players and transport controls in the persistent media row. This implementation avoids additional perpetual work but does not establish a measured frame-rate guarantee. Existing artwork crossfades, media progress, color cycling and idle collapse retain their own behavior. Performance and legibility still need checking under the user's live media/camera load.

The user's 2026-11-19 refinement puts media-only cards directly above the ordinary summary tiles in one row spanning the available dashboard width. The row uses the same natural height as a Glass player: 76 dp artwork plus 4 dp padding above and below, totaling 84 dp. Compact artwork/metadata and adjacent transport controls fit below the central overview; controls use two rows in narrow player tiles. This replaces the oversized height of up to 160 dp / 38% of the viewport. Visible players across those cards receive equal widths; hidden players reserve an equal slot only when Keep space empty is saved. Mixed cards remain ordinary summaries/panels. Player tiles reuse HAL artwork and playback metadata, and expose Previous, Play/Pause, Stop and Next buttons. Each command rechecks the latest state, connection and advertised Home Assistant feature bit before dispatch; unsupported/unavailable buttons remain visible and focusable for remote navigation but do nothing. Home focus and focus recovery can target the persistent players without opening a panel.

Calm summary tiles show a lock-state icon at the upper-right when a visible configured lock is present. An unlocked lock takes priority over other locks; otherwise a fault or unknown state takes priority over a secure state, and green locked requires every visible lock to be locked. Hidden/reserved lock rows do not leak into the badge; a configured lock with missing live state is unknown. The icon is informational; normal lock actions remain inside the card.

## Other integrations and diagnostics

Cameras use Media3 RTSP with optional grid substreams. Live slots depend on device decoder capacity; snapshots cover cameras that are not live. Do not equate successful APK installation with successful hardware decoding. Frigate shows alerts from the last seven days and full-screen clips. Camera snapshots and logs are local retained data, distinct from uploaded slideshow files.

The network icon describes Android's default connection and usable addresses; it is not a Home Assistant health indicator or proof of internet access. Build status from capabilities and link properties for the same callback network, waiting for both and ignoring replaced-network events. Synchronous connectivity reads inside callbacks previously produced a false disconnected icon.

**Download HAL logs** uses `/api/logs` under the same editor listener checks and returns `hal-logs.txt`. Retention defaults to 12 hours and is configurable from 1–72 hours. Logs include recorded crash traces and use credential scrubbing; do not promise that every private value is removed. Reopen HAL and enable the editor after a crash to retrieve them.

The Home helper is optional and requires Android Accessibility permission plus a HAL override setting. Catching Home avoids the stock launcher's delay but can affect held volume-key repeat; reopening after the stock launcher appears is a separate option. Repeated failed launches switch the override off to preserve access to the device. This is not automatic default-launcher registration on every TV.
